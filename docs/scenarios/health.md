# Scenarios: can Aegida still watch?

What Android does to the notification listener (snooze returning, unbinding after an update or restart, binding again), what goes
over the network compared with the privacy page, and what Home says in each state. Each row names the test that covers it. `GAP`
means nothing covers it yet. Findings #111 (notices that came while Aegida was not listening) and #112 (access on, but not
listening) were approved by Kevin on Oct 14. Source: [test-review.md](../test-review.md) gaps 3, 4 and 8.

Finding #134 (Oct 14): on the emulator Android never called `onListenerDisconnected` (disallow/allow, Settings off/on, force-stop
all rebind without it), so neither H3 nor H4 depends on it. The listener service sets an in-process "bound now" flag when it is
bound and clears it in `onListenerDisconnected` and `onDestroy`; a new process starts with it clear. Every check that runs while it
is set records "last seen bound" when it finishes (one setting, no migration; finding #141), and every notice the listener hears
runs such a check. H3 checks the
notices posted after the last time a check saw it bound; H4 counts from that time (or from the last restart or Aegida's install or
update, whichever is latest).

`HealthScenariosTest` drives the checks through `FakeNotificationShade` (core test fixtures), which follows Android's documented
listener behaviour; its listener does what `AegidaListenerService` does (that class needs Hilt and is not run on the JVM). The shade
has not been compared with an emulator trace yet.
